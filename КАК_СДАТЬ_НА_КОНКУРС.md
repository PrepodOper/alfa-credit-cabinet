Всё, что нужно жюри, уже лежит в репозитории — остаётся выложить его на GitHub
и заполнить форму.

## 1. Проверить репозиторий перед отправкой

Откройте терминал в папке проекта:

```cmd
cd C:\Users\DENYA228\Desktop\alfa-credit-cabinet
```

```cmd
git status
git log --oneline -5
git tag -l
```

Ожидаемо:

- `git status` → `nothing to commit, working tree clean`;
- в логе последние коммиты от 24 октября;
- теги: `v1.0.0` и `v1.1.0`.

Если `git status` показывает изменения — закоммитьте их:

```cmd
git add -A
git -c user.name="Ваше Имя" -c user.email="you@example.com" commit -m "ваше сообщение"
git tag -f v1.1.0
```

> Если `git` пишет `not recognized` — установите Git for Windows: https://git-scm.com/download/win
> (при установке оставьте по умолчанию, Git Bash не обязателен).

## 2. Создать репозиторий на GitHub

1. Войдите на https://github.com → **+** (справа сверху) → **New repository**.
2. Заполните:
   - **Repository name:** `alfa-credit-cabinet`
   - **Description:** `Цифровой кредитный конвейер для МСБ: клиентский кабинет, скоринг, ручное рассмотрение — Альфа-Хак 2026`
   - **Public** — рекомендуется (жюри откроет по ссылке без доступа; приватность ниже).
   - **НЕ** ставьте галочки «Add a README», «Add .gitignore», «Choose a license» — репозиторий должен быть пустым, иначе будет конфликт при первом пуше.
3. Нажмите **Create repository**. GitHub покажет страницу с командами — они нам и нужны.

### Если репозиторий приватный

Это разрешено, но тогда **обязательно** выдать доступ аккаунту жюри:

**Settings** → **Collaborators** (или *Collaborators and teams*) → **Add people** →
ввести `alfa-hack-2026` → роль **Read** → **Add**.

Без этого жюри не увидит ни код, ни тег, ни историю — работу просто не проверят.
Проверить, что доступ выдан: имя `alfa-hack-2026` должно появиться в списке коллабораторов.

## 3. Привязать удалённый репозиторий и запушить

В папке проекта (замените `ВАШ-ЛОГИН` на свой):

```cmd
git remote add origin https://github.com/ВАШ-ЛОГИН/alfa-credit-cabinet.git
```

Переименуйте ветку в `main` (GitHub использует её по умолчанию):

```cmd
git branch -M main
```

Отправьте ветку и **обязательно теги** (без `--tags` жюри не увидит версию):

```cmd
git push -u origin main
git push origin --tags
```

При первом пуше Git спросит логин и пароль. Пароль от GitHub **не подойдёт** — нужен
Personal Access Token:

1. https://github.com/settings/tokens → **Generate new token (classic)**
2. Note: `alfa-hack`, Expiration: 90 days, галочка **repo**
3. **Generate token**, скопировать (`ghp_...`) и вставить вместо пароля.

> Вместо токена можно поставить GitHub CLI (`winget install GitHub.cli`, затем `gh auth login`) —
> тогда авторизация в браузере в один клик.

Если remote уже был (повторная отправка):

```cmd
git remote set-url origin https://github.com/ВАШ-ЛОГИН/alfa-credit-cabinet.git
git push -u origin main --force
git push origin --tags --force
```

## 4. Проверить, что на GitHub всё на месте

Откройте страницу репозитория и проверьте:

- [ ] в шапке виден список файлов: `backend/`, `frontend/`, `docs/`, `README.md`, `docker-compose.yml`;
- [ ] под названием — счётчик коммитов (20+);
- [ ] справа в блоке **Releases** / во вкладке **Tags** (значок тега рядом с веткой) есть `v1.1.0` и `v1.0.0`;
- [ ] README отображается с картинкой дашборда и оглавлением;
- [ ] в репозитории **нет** файла `.env` (там был бы секрет) — есть только `.env.example`.

Командой (надёжнее, чем глазами):

```cmd
git ls-remote --tags origin
```

Должно показать `refs/tags/v1.0.0` и `refs/tags/v1.1.0`.

## 5. Зафиксировать идентификатор версии

Жюри просит commit hash, тег или иной однозначный идентификатор **на момент дедлайна**.
Возьмите значение из репозитория:

```cmd
git rev-parse HEAD
git describe --tags
```

Что вписать в форму:

| Поле для формы | Значение |
|---|---|
| Тег | `v1.1.0` |
| Коммит | результат `git rev-parse HEAD` — впишите в момент сдачи |
| Ветка | `main` (локально `master`, переименовывается в шаге 3) |

> Хеш не указан здесь специально: любой новый коммит (даже правка README) меняет его.
> Возьмите актуальное значение командой `git rev-parse HEAD` непосредственно перед отправкой
> формы. Тег `v1.1.0` при этом остаётся привязанным к помеченной версии — его безопаснее
> указывать как основной идентификатор, а хеш — дополнительно.

## 6. Проверка «как у судьи» — 5 минут

Самый частый способ потерять баллы: у автора всё работает, у проверяющего — нет.
Проверьте так, как будто вы никогда не видели проект:

1. Склонируйте репозиторий в **другую папку**:

   ```cmd
   cd %TEMP%
   git clone https://github.com/ВАШ-ЛОГИН/alfa-credit-cabinet.git check-submission
   cd check-submission
   ```

2. Запустите Docker-способ (как описано в README):

   ```cmd
   docker compose up --build
   ```

3. Откройте http://localhost:8080 → войдите `ivan@vesna.ru` / `demo1234` → подайте заявку →
   дождитесь оферты → примите → подпишите → «Кредит выдан». Затем «Сменить роль» →
   `underwriter@alfabank.ru` → раздел `/bank` → откройте заявку → график платежей виден.
4. Тесты (по желанию, требует Python 3.11+):

   ```cmd
   cd backend
   python -m venv .venv
   .venv\Scripts\python.exe -m pip install -r requirements.txt pytest httpx
   set DEMO_DELAY_SCALE=0
   .venv\Scripts\python.exe -m pytest
   ```

   Ожидаемо: `21 passed`.

5. Удалите проверочную папку: `rmdir /s /q check-submission`.

> Проверка воспроизведена в чистом окружении: клон → `./start.sh` → `/api/health` 200,
> SPA 200, `/api/company` отдаёт профиль.

## 8. Публикация в облаке — Amvera (готовая конфигурация)

Кейс просит «заранее завести решение на бесплатном внешнем сервере». Всё подготовлено:

- `Dockerfile.allinone` — один контейнер, в котором FastAPI раздаёт и API, и собранный фронтенд;
- `amvera.yaml` — конфигурация сборки и запуска (`containerPort: 8000`, `persistenceMount: /data`);
- `Dockerfile.static` — резервный образ без сборки Node, если на дешёвом тарифе не хватит памяти;
- `РАЗВЁРТЫВАНИЕ_AMVERA.md` — пошаговая инструкция с разбором ошибок.

Коротко:

```cmd
git remote add amvera https://git.msk0.amvera.ru/ВАШ_ЛОГИН/ИМЯ_ПРОЕКТА
git push amvera main:master
```

Через 3–6 минут вкладка «Настройки» → включить бесплатный домен →
`https://ИМЯ_ПРОЕКТА-ВАШ_ЛОГИН.msk1.amvera.tech` (HTTPS настраивается платформой).
Тариф «Начальный» — 290 ₽/мес, тарификация поминутная, между показами проект можно ставить на паузу.

Другие платформы (Render, Koyeb, Railway, Timeweb Cloud Apps) принимают тот же
`Dockerfile.allinone` — см. приложение в инструкции.

## 9. Типичные проблемы

| Симптом | Причина и решение |
|---|---|
| `remote: Repository not found` | ошибка в логине/имени репозитория или нет прав. Проверьте URL: `git remote -v`, права токена (`repo`) |
| `src refspec main does not match any` | ветка ещё не переименована: `git branch -M main` |
| `failed to push some refs` / `non-fast-forward` | в удалённом репозитории уже есть коммиты (создали с README). Либо `git push -u origin main --force`, либо пересоздайте пустой репозиторий |
| `Authentication failed` | вместо пароля нужен Personal Access Token (шаг 3) |
| Просит пароль при каждом пуше | `git config --global credential.helper manager` (Windows) |
| Не видно тегов на GitHub | забыли `git push origin --tags` |
| Большой репозиторий / «файл больше 100 МБ» | в проекте таких нет (крупнейший — презентация 2,3 МБ); если добавили своё видео — вынесите в YouTube/диск и дайте ссылку в README |
| Судья не может клонировать | репозиторий приватный, а `alfa-hack-2026` не добавлен в коллабораторы (шаг 2) |
| Хочу, чтобы коммиты были подписаны моим именем | ниже, необязательный шаг |

### Необязательно: переписать автора коммитов на себя

Сейчас все коммиты подписаны техническим алиасом `Alfa Credit Cabinet Team`. Если хотите,
чтобы история была на вашем аккаунте GitHub, выполните один раз **до** пуша:

```cmd
git config user.name "Ваше Имя"
git config user.email "ваш-github-email@example.com"

git filter-branch --env-filter ^
"if [ $GIT_AUTHOR_EMAIL = 'team@alfa-credit-cabinet.local' ]; then export GIT_AUTHOR_NAME='Ваше Имя'; export GIT_AUTHOR_EMAIL='ваш-github-email@example.com'; fi; if [ $GIT_COMMITTER_EMAIL = 'team@alfa-credit-cabinet.local' ]; then export GIT_COMMITTER_NAME='Ваше Имя'; export GIT_COMMITTER_EMAIL='ваш-github-email@example.com'; fi" ^
--tag-name-filter cat -- --branches --tags
```

Команда выполняется в **Git Bash** (не в cmd) — там синтаксис с `if` работает как есть.
После неё хеши коммитов изменятся: заново поставьте тег (`git tag -f v1.1.0`) и возьмите
новый `git rev-parse HEAD` для формы. Даты и состав коммитов сохранятся.
