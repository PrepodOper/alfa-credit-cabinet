# Развёртывание на Amvera Cloud

Пошаговая инструкция: как поднять этот проект на российском PaaS [amvera.ru](https://amvera.ru)
и получить публичную ссылку вида `https://alfa-credit-cabinet-вашлогин.amvera.io`.

В репозитории уже лежит всё необходимое:

| Файл | Зачем |
|---|---|
| `amvera.yaml` | конфигурация сборки/запуска для Amvera |
| `Dockerfile.allinone` | **один** контейнер: FastAPI раздаёт и API, и React-фронтенд |
| `Dockerfile.static` | резервный вариант того же контейнера без сборки Node (если сборка не влезает в память) |
| `docker-entrypoint.sh` | запуск uvicorn на порту из `PORT`, проверка каталога `/data` |
| `.dockerignore` | чтобы в образ не попали `.git`, `node_modules`, база и скриншоты |

> Почему не `docker-compose.yml`: в нём два контейнера (backend + nginx). Amvera поднимает
> **один** контейнер, поэтому фронтенд собирается внутри `Dockerfile.allinone` и раздаётся
> тем же FastAPI через `STATIC_DIR` — ровно как в `./start.sh`.

## 0. Что понадобится

- Аккаунт на amvera.ru (регистрация по e-mail, приветственный баланс **111 ₽** на тест).
- Git на компьютере (уже нужен был для GitHub).
- ~15 минут на первый деплой (сборка образа 3–6 минут).

### Тариф

| Тариф | Цена | Ресурсы | Подходит? |
|---|---|---|---|
| **Пробный** | 170 ₽/мес (0,24 ₽/час) | 0,1 ГБ RAM, 2 ГБ диска, 0,1 vCPU | впритык: Python + SQLite могут не влезть в 100 МБ |
| **Начальный** | 290 ₽/мес (0,4 ₽/час) | 0,5 ГБ RAM, 5 ГБ диска | **рекомендую** — стабильно для демо и защиты |

Тарификация **поминутная**: можно включить проект на время проверки, а потом поставить на паузу.
Месяц на «Начальном» ≈ 290 ₽, две недели ≈ 135 ₽.

## 1. Создать проект в Amvera

1. Войдите в личный кабинет: https://amvera.ru → **Войти**.
2. Нажмите **«Создать проект»**.
3. Тип сервиса — **«Приложение»** (подходит для любого кода).
4. Заполните:
   - **Название:** `alfa-credit-cabinet` (латиницей; из него получится домен);
   - **Тариф:** «Начальный» (или «Пробный», если хотите проверить бесплатно);
   - регион — любой предложенный.
5. Нажмите **«Далее»** и дождитесь создания. Откроется этап **«Загрузка данных»**.

Ничего не загружайте через веб-интерфейс: код поедет через git.

---

## 2. Отправить код в репозиторий Amvera

У каждого проекта Amvera есть свой git-репозиторий. Ссылка видна во вкладке **«Репозиторий»**,
блок «Или подключить к существующему репозиторию».

В папке проекта (там, где лежит `amvera.yaml`):

```cmd
cd C:\Users\DENYA228\Desktop\alfa-credit-cabinet
```

```cmd
git remote add amvera https://git.amvera.ru/ВАШ_ЛОГИН/alfa-credit-cabinet
```

Проверьте, что remote добавился (должны быть и `origin` для GitHub, и `amvera`):

```cmd
git remote -v
```

Отправьте код в ветку `master` (Amvera собирает именно её):

```cmd
git push amvera master
```

Если вашу ветку переименовывали в `main` (это делается при выкладке на GitHub), команда другая:

```cmd
git push amvera main:master
```

Git спросит логин и пароль — это **учётная запись Amvera**, не GitHub.
После пуша в кабинете автоматически начнётся сборка.

> **Альтернатива:** вместо git-remote можно привязать GitHub-репозиторий в интерфейсе Amvera
> (этап «Загрузка данных» → подключить репозиторий). Тогда каждый `git push origin main`
> будет запускать пересборку. Для конкурса проще и надёжнее первый вариант: код лежит
> в двух местах, но никаких танцев с доступами между сервисами.

## 3. Задать переменные окружения

Вкладка **«Переменные»** проекта. Значения из `Dockerfile.allinone` работают и так, но два
параметра лучше задать явно:

| Название | Значение | Тип | Зачем |
|---|---|---|---|
| `JWT_SECRET` | длинная случайная строка (32+ символа) | **секрет** | подпись токенов; дефолтное значение из кода в проде недопустимо |
| `TIMING_PROFILE` | `demo` | переменная | быстрый показ (~2 с на автопроверку); `realistic` — ~3 минуты |
| `DEMO_DELAY_SCALE` | `1.0` | переменная | множитель пауз; `0` — мгновенно |
| `SEED_ON_START` | `true` | переменная | создать синтетические данные при первом старте |
| `CORS_ORIGINS` | `*` | переменная | фронтенд и API на одном origin, можно оставить `*` |

Уже зашиты в образ (менять не обязательно): `DATABASE_URL=sqlite:////data/credit_cabinet.db`,
`STATIC_DIR=/app/static`, `PORT=8000`.

> Переменные применяются **после перезапуска** контейнера (кнопка «Перезапустить»).
> Значения-секреты после сохранения в интерфейсе не отображаются — это нормально.

Сгенерировать секрет (Windows, PowerShell):

```powershell
-join ((48..57) + (65..90) + (97..122) | Get-Random -Count 48 | % {[char]$_})
```

## 4. Дождаться сборки и открыть сайт

1. Вкладка **«Сборка»** (или «Логи сборки») — идёт `docker build` по `Dockerfile.allinone`:
   сначала `npm ci` + `vite build`, затем установка Python-зависимостей.
   Первая сборка 3–6 минут, последующие быстрее (кеш слоёв).
2. Когда статус станет **«Успешно развернуто»**, вкладка **«Настройки»** → включите
   **бесплатное доменное имя Amvera**.
3. Ссылка будет вида:

```
https://alfa-credit-cabinet-ВАШ_ЛОГИН.amvera.io
```

HTTPS-сертификат Amvera выпускает сама — ничего настраивать не нужно.

Проверьте:

- `https://…amvera.io/api/health` → `{"status":"ok", ..., "timing_profile":"demo", "auto_branch_seconds":1.9}`
- `https://…amvera.io/` → страница входа
- `https://…amvera.io/docs` → Swagger

## 6. Где хранятся данные

Amvera монтирует папку постоянного хранилища `Data` в контейнер по пути из
`run.persistenceMount` — у нас `/data` (см. `amvera.yaml`).

- база: `/data/credit_cabinet.db` (+ `-wal`, `-shm` рядом);
- папка переживает перезапуски и пересборки;
- посмотреть файлы: вкладка **«Репозиторий»** → папка **Data** (появляется после первого
  успешного деплоя);
- сбросить демо-данные: удалить `credit_cabinet.db*` в папке Data и перезапустить контейнер —
  при старте база создастся заново и наполнится синтетикой.

> Если базу положить в `/app/data` (внутри образа) — она **пропадёт** при следующей пересборке.
> Именно поэтому в `Dockerfile.allinone` путь абсолютный и указывает в `/data`.

## 7. Обновление, пауза и стоимость

**Обновить сайт** после правок:

```cmd
git add -A
git commit -m "описание изменений"
git push amvera master
```

**Обновить и GitHub одновременно:**

```cmd
git push origin main
git push amvera master
```

**Остановить начисление денег** (например, между показом и защитой): вкладка «Настройки» →
**«Остановить»** / «Пауза». Данные в Data сохраняются. При включении обратно проект поднимется
с тем же образом и базой.

**Тариф сменить** можно в «Настройках» в любой момент, пересборка не нужна.

## 8. Проблемы и решения

| Симптом | Причина | Что делать |
|---|---|---|
| **503 Service Unavailable** после деплоя | приложение слушает не тот порт, что указан в `containerPort` | в `amvera.yaml` должно быть `containerPort: 8000`; в логах приложения — `Uvicorn running on http://0.0.0.0:8000` |
| **502 Bad Gateway** | контейнер упал или ещё стартует | вкладка «Логи» → «Логи приложения»; чаще всего ошибка импорта или занятый порт |
| Сборка падает на `npm ci` / «Killed» | не хватило памяти на этапе сборки фронтенда | переключиться на готовый образ без Node: в `amvera.yaml` заменить `dockerfile: Dockerfile.allinone` на `dockerfile: Dockerfile.static` (использует закоммиченный `frontend/dist`) и запушить снова. Либо взять тариф повыше |
| **Данные исчезли после пересборки** | база лежала в `/app/...`, а не в `/data` | проверить `DATABASE_URL=sqlite:////data/credit_cabinet.db` (четыре слэша!) и `run.persistenceMount: /data` |
| `sqlite3.OperationalError: unable to open database file` | каталог `/data` недоступен для записи | в логах приложения будет строка `[warn] Каталог … недоступен для записи`; проверить `persistenceMount` |
| **`database is locked`** под нагрузкой | несколько воркеров пишут в SQLite | у нас один процесс uvicorn; не добавляйте `--workers >1` на SQLite, либо переходите на PostgreSQL |
| Сайт открывается, но белый экран | не собран фронтенд (`STATIC_DIR` пуст) | проверить, что в образе есть `/app/static/index.html` (стадия `frontend` в Dockerfile) |
| `Permission denied` при push | неверный логин/пароль Amvera | логин и пароль — от аккаунта amvera.ru; при включённой 2FA используйте токен из настроек профиля |
| `! [rejected] master -> master` | в репозитории Amvera уже есть коммиты (например, вы правили конфигурацию в интерфейсе) | `git pull amvera master --rebase` затем повторный push, либо `git push amvera master --force` (если в облаке нет нужных правок) |
| Долго холодный старт | контейнер «засыпает» на дешёвом тарифе | первый запрос после паузы — до 10–20 секунд; предупредите жюри или держите проект активным на время проверки |
| Не видно папку Data | деплой ещё ни разу не был успешным | папка создаётся на этапе развёртывания; сначала добейтесь статуса «Успешно развернуто» |

Полезные места в кабинете: **«Логи»** (сборка / приложение / система), **«Переменные»**,
**«Репозиторий»** (Code и Data), **«Настройки»** (домен, тариф, стоп/старт).

## 9. Своё доменное имя (необязательно)

1. «Настройки» → **«Добавить домен»** → введите, например, `credit.вашдомен.ru`.
2. У регистратора домена создайте записи, которые покажет Amvera (обычно `A` на IP платформы
   и `TXT` для подтверждения владения).
3. Дождитесь выпуска сертификата (несколько минут). DNS может обновляться до пары часов.

Для конкурса достаточно бесплатного домена `*.amvera.io` — он выглядит нормально и работает по HTTPS.

## Приложение. Те же файлы для других платформ

`Dockerfile.allinone` — обычный Docker-образ, поэтому он подходит и для Render, Koyeb,
Railway, Selectel, Timeweb Cloud Apps:

```bash
docker build -f Dockerfile.allinone -t alfa-credit-cabinet .
docker run -p 8000:8000 -v alfa_data:/data -e JWT_SECRET=change-me alfa-credit-cabinet
# → http://localhost:8000
```

Отличия от `docker-compose.yml` — только в том, что нет отдельного nginx: статику отдаёт FastAPI.
На VPS с Docker Compose (например, на Timeweb/Selectel) удобнее использовать
`docker compose up --build` из корня — эта схема описана в `КАК_ЗАПУСТИТЬ.md`.
